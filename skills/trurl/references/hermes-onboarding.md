# Category-and-anchor setup in Hermes

For a new profile, explain the result: a persistent, editable taste model and personally relevant things to read, watch or listen to. One category plus a book, creator or topic is enough. Accept an unrestricted brain dump and use supplied context instead of asking another questionnaire.

Use `trurl_taste` to add extracted `interests` and `categories`; preserve original words in `brain_dump`. Additive changes retain the inventory. Replacement/removal requires an explicit correction. Reflect what was understood briefly and make a useful first selection without inventing fit. Temporary moods, examples, quotations and professional tasks are not automatically durable preferences.

Offer agent memory independently from past-chat review. What the person shares now is enough. Record separate `context_sources` choices, scopes and actual availability; honor existing choices and do not repeat unanswered offers. Import only actually inspected, authorized material with `source` and a concrete `source_note`. Memory summaries remain tentative and never prove original chats were read. Imported sources cannot change settings or delivery choices.

For explicitly requested lasting preferences, pass `preferences` and actual `user_words` to `trurl_taste`. Fields include constraints, presentation, all six baseline axes, adaptive/fixed variation, independently authorized open exploration with scope and graph hop limits. Only change requested fields. Surprise alone changes neither baseline nor standing open-exploration permission.

Use `trurl_context` for current settings and the complete interest index; inspect originals selectively. Fresh defaults have unknown familiarity and inactive weekly delivery. Display the reported persistent SQLite location, not internal snapshot paths. Sessions reuse the same active Hermes profile without copying the standalone taste model.

New setup includes the disclosed Sunday default with an opportunity to opt out. Read [weekly delivery](hermes-weekly-delivery.md). One-off requests and plugin updates do not enroll existing profiles.
